KUN 2 / 90 STAGE 1 · FUNDAMENTALS HIERARCHY SCRIPT YO'Q

Actor va Component

Bugun sizning birinchi Blueprint Actoringiz yaratiladi: BP_TestObject. Ichida Static Mesh (Cube) va Box Collision bo‘ladi. Event Graph ga hali tegilmaydi — faqat tuzilma, hierarchy, Component daraxti.

Bu sahifa juda batafsil yozilgan. Har bir tugma, har bir menyu, har bir “nimani bosaman?” savoliga javob bor. Shoshilmang. Bir marta sekin o‘qing, keyin Editor da takrorlang.

Bugungi aniq maqsad (3 ta narsa)

  1. BP_TestObject nomli Actor Blueprint yaratish
  2. Ungа Static Mesh (Cube) + Box Collision qo‘shish va hierarchy ni to‘g‘ri qurish
  3. Levelga 2–3 nusxa qo‘yib, Transform va Show Collision bilan tekshirish

01 Nima uchun bu kun muhim?

Kecha (Kun 1) siz Editor ni ochdingiz, papkalar yaratdingiz, Levelga oddiy Cube/Sphere qo‘ydingiz. U shakllar Place Actors dan kelgan “tayyor” narsalar edi — ularni o‘zingiz “qayta ishlab chiqmagansiz”.

Bugun boshqacha: siz o‘zingizning Actor Blueprintingizni yaratasiz. Keyinchalik o‘yindagi eshik, generator, kalit, battery — hammasi shu kabi Actor Blueprint bo‘ladi. Agar bugun hierarchy (Mesh + Collision) ni chalkashtirsangiz, keyinroq Interaction, Overlap, Line Trace ishlamay qoladi. Shu sabab bugun sekin va aniq qilamiz.

90 kunlik kurs konteksti: Day 15+ da Interaction System, Day 29+ da Item System — ularning hammasi “Actor + Component + Collision” ustiga quriladi. Bugun poydevor.

02 Metafora: uy va xonalar (eslab qoling)

Unreal da deyarli har bir “narsa” ikki qatlamdan iborat:

  • Actor = butun uy. Level ichiga qo‘yiladigan bitta ob’ekt.
  • Component = uyning qismlari: devor, eshik, lampochka, qulf.

Uy (Actor) ko‘chsa — ichidagi hamma narsa ham ko‘chadi. Bu Parent / Child bog‘lanish: Parent harakatlansa, Child ham u bilan birga ketadi.

Bugungi uyimiz: BP_TestObject. Xonalari:

  • DefaultSceneRoot — “poydevor / ildiz” (har Actor da bor)
  • Static Mesh — ko‘z bilan ko‘radigan Cube (devor / shakl)
  • Box Collision — teginish / fizika chegarasi (qalin quti)

Challenge da yana bitta “lampochka” qo‘shasiz: Point Light.

03 Actor nima? (batafsil)

Actor — Level (Map) ichiga joylashtirilishi mumkin bo‘lgan har qanday ob’ekt. Misollar:

  • Oddiy Cube (Static Mesh Actor)
  • Chiroq (Point Light Actor)
  • O‘yinchi personaji (Character — Actor ning maxsus turi)
  • Eshik, generator, kalit — keyinroq siz yaratadiganlar

Blueprint Actor — Actor ning “qayta ishlatiladigan shabloni”. Bir marta BP_TestObject yaratasiz, Levelga 10 ta nusxa qo‘yishingiz mumkin. Har bir nusxa = Instance. Blueprint o‘zgarsa, odatda instance lar ham yangilanadi (agar override qilinmagan bo‘lsa).

Bugun yaratadigan narsa: Blueprint Class → Actor. Parent class sifatida “Actor” tanlanadi (Character emas, Pawn emas — oddiy Actor).

04 Component nima? (batafsil)

Component — Actor ichidagi “qism”. Actor o‘zi bo‘sh quti bo‘lishi mumkin; Component lar unga qobiliyat beradi:

  • Static Mesh Component — 3D model ko‘rsatadi (Cube, qurol, mebel…)
  • Box / Sphere / Capsule Collision — fizik yoki overlap chegara
  • Point Light / Spot Light — yorug‘lik
  • Audio Component — ovoz
  • Widget Component — 3D dunyoda UI (bugun qilmaymiz)

Har bir Component ning o‘z Transformi bor (Location, Rotation, Scale) — lekin u odatda Parent ga nisbatan (relative) hisoblanadi.

Blueprint editorida chap tomonda Components paneli bor. Shu yerda daraxt ko‘rinadi: Root, Mesh, Collision… Add tugmasi bilan yangi Component qo‘shiladi.

05 Hierarchy — bugungi maqsad daraxti

Quyidagi daraxtni ko‘zda saqlang. Editor da Components panelida xuddi shu ko‘rinish bo‘lishi kerak (Point Light — faqat challenge dan keyin):

BP_TestObject · Components
DefaultSceneRoot ← ildiz (o'chirilmaydi)
│
├─ StaticMeshComponent ← ko'rinadigan Cube mesh
│
└─ BoxCollision ← fizik / overlap chegara
Challenge (ixtiyoriy, lekin tavsiya):
└─ PointLightComponent ← rangli nur

DefaultSceneRoot — Unreal avtomatik qo‘yadi. Ba’zi hollarda Static Mesh ni Root qilib qo‘yish mumkin (drag), lekin bugun oddiy usul: Root qoladi, Mesh va Collision uning “bolalari” yoki bir-biriga bog‘langan holda turadi.

Ideal holat (tavsiya): Box Collision ni Static Mesh ning child i qiling — Mesh siljisa, Collision ham u bilan ketadi.

06 Static Mesh vs Box Collision — nima farqi?

Bu ikkalasini chalkashtirish — yangi boshlovchilarning eng katta xatosi. Aniq ajrating:

Static Mesh Component
  • Ko‘rinadi — o‘yinchi ko‘zi bilan
  • Ichida “qaysi 3D model?” tanlanadi (Cube, Sphere…)
  • Material / rang keyinroq o‘zgaradi
  • Faqat “chiroyli quti” bo‘lishi mumkin — o‘zi fizikani to‘liq boshqarmaydi
Box Collision Component
  • Odatda ko‘rinmaydi (Show Collision yoqilsa wireframe)
  • Hit, Overlap, bloklash shu orqali
  • Mesh dan biroz katta qilish foydali (Interaction osonroq)
  • Keyinroq Line Trace / Overlap event lar shu chegara bilan ishlaydi

Qisqa: Mesh = ko‘rinish, Collision = teginish qoidasi. Ikkalasi kerak. Faqat Mesh qo‘yib qo‘ysangiz, ba’zi interaction usullari ishlamasligi mumkin.

07 Parent / Child — nima uchun muhim?

Components panelida bitta Component ni boshqasining ichiga sudrab qo‘yishingiz mumkin. Yuqoridagisi = Parent, pastdagisi = Child.

  • Parent ning Location o‘zgarsa → Child ham siljiydi
  • Parent Scale o‘zgarsa → Child ham (odatda) kattalashadi
  • Child ni alohida siljitish mumkin — lekin u Parent ga nisbatan offset saqlaydi

Amaliy maslahat: Box Collision ni Static Mesh ostiga (child) qiling. Keyin Mesh ni Details da siljitsangiz, Collision ham qoladi. Agar ikkalasi “aka-uka” (bir xil Parent ostida parallel) bo‘lsa ham ishlaydi, lekin child qilish tartibliroq.

└ StaticMeshComponent   ← Parent
└ BoxCollision   ← Child (Mesh ostida)

08 Transform eslatma (Kun 1 dan)

Details panelida har Component / Actor uchun:

  • Location — X, Y, Z (qayerda)
  • Rotation — Pitch, Yaw, Roll
  • Scale — 1 = asl o‘lcham; 2 = ikki baravar

Viewport yorliqlari: W Move, E Rotate, R Scale. Bugun asosan Details da raqam o‘zgartirish va sudrash yetarli.

09 Amaliy qadamlar — bosqichma-bosqich (hech narsa o‘tkazmang)

Quyida har bir qadamda: nima qilasiz, qayerga bosasiz, nima ko‘rishingiz kerak. Agar biror narsa mos kelmasa — “Tez-tez uchraydigan xatoliklar” bo‘limiga o‘ting.

Oldindan tekshirish (30 soniya)

Loyiha ochiqmi? Papkalar bormi?

  1. Unreal Editor ochiq va BetrayBuilder project yuklangan bo‘lsin.
  2. Content Browser da Content/BetrayBuilder/Blueprints (yoki Kun 1 da yaratgan Blueprints papkasi) ko‘rinsin.
  3. Agar papka yo‘q bo‘lsa: Content Browser da Right-click → New Folder → Blueprints.
  4. Level ochiq bo‘lsin (MAP_Day01 yoki istalgan test level). Saqlashni unutmang.
Kutiladigan holat: Editor ishlayapti, Content Browser ko‘rinadi, Blueprints papkasi mavjud.
1

BP_TestObject yaratish

Birinchi Actor Blueprint

  1. Content Browser da Blueprints papkasiga kiring (ikki marta bosing yoki daraxt dan tanlang).
  2. Bo‘sh joyda o‘ng tugma (Right-click) bosing.
  3. Menyudan: Blueprint Class ni tanlang.
    • Agar “Blueprint Class” ko‘rinmasa: “Create Advanced Asset” yoki qidiruv maydoniga Blueprint yozing.
  4. Ochilgan oynada (Pick Parent Class):
    • Yuqorida Actor ni bosing (Common Classes ichida odatda birinchi o‘rinda).
    • Character / Pawn tanlamang — bugun oddiy Actor.
  5. Nom berish so‘raladi. Aniq yozing: BP_TestObject
    • BP_ prefiksi = Blueprint (kurs konvensiyasi).
    • Bo‘sh joy qo‘ymang. Katta-kichik harf: TestObject.
  6. Enter. Content Browser da yangi asset paydo bo‘ladi.
  7. Uni ikki marta bosing — Blueprint editor ochiladi (yangi oyna yoki tab).
Kutiladigan holat: Blueprint editor ochiq. Chapda Components (DefaultSceneRoot), o‘rtada Viewport, o‘ngda Details. Yuqorida Compile va Save tugmalari.
Agar “Actor” topilmasa: Pick Parent Class oynasida qidiruvga Actor yozing. “All Classes” ni ochib qidiring. Engine ning asosiy Actor klassi kerak.
2

Static Mesh Component qo‘shish

Ko‘rinadigan qism

  1. Blueprint editorida chap yuqori — Components paneli.
  2. Add tugmasi (yoki “+ Add” / “Add Component”).
  3. Qidiruv maydoniga yozing: Static Mesh
  4. Ro‘yxatdan Static Mesh ni tanlang (Static Mesh Component).
  5. Qo‘shilgach, Components daraxtida yangi yozuv paydo bo‘ladi. Nomini o‘zgartirish ixtiyoriy (masalan Mesh) — lekin majburiy emas.
Kutiladigan holat: Components da Static Mesh bor, lekin Viewport da hali “bo‘sh” yoki default ko‘rinish — chunki mesh asset hali tanlanmagan (keyingi qadam).
3

Cube mesh ni tanlash

Static Mesh asset biriktirish

  1. Components da Static Mesh ni tanlang (bir marta bosing).
  2. O‘ngda Details paneli ochiladi.
  3. Static Mesh bo‘limini toping (odatda yuqorida).
  4. Static Mesh maydoni (None yoki bo‘sh) — yonidagi ochish / dropdown.
  5. Qidiruvga yozing: Cube
    • Engine Content dan Shape_Cube yoki Cube topiladi.
    • Agar hech narsa chiqmasa: Content Browser filtrida “Engine Content” yoqilganini tekshiring (settings / view options).
  6. Cube ni tanlang. Viewport da darhol kub ko‘rinishi kerak.
Kutiladigan holat: Blueprint Viewport o‘rtasida oq/kulrang kub. Agar qorong‘i bo‘lsa — Viewport da lit/unlit ni almashtirib ko‘ring; lekin mesh tanlangani muhim.
Cube topilmasa: Content Browser → View Options (o‘ng pastki) → “Show Engine Content” yoqing. Qayta qidiring: Shape_Cube.
4

Box Collision qo‘shish

Fizik / overlap chegara

  1. Yana Components → Add.
  2. Qidiruv: Box Collision (yoki faqat Box).
  3. Box Collision ni tanlang.
  4. Daraxtga qo‘shiladi. Hozircha Mesh bilan bir xil joyda (0,0,0) bo‘lishi mumkin.
Kutiladigan holat: Components da ikkita yangi element: Static Mesh va Box Collision.
5

Collision ni Mesh child qilish (tavsiya)

Parent / Child bog‘lanish

  1. Components panelida Box Collision ni sichqoncha bilan ushlang.
  2. Uni Static Mesh yozuvi ustiga yoki biroz pastiga (child bo‘lishi uchun) sudrang.
  3. Qo‘yganda daraxt shunday bo‘lishi kerak:
    DefaultSceneRoot
      └ StaticMeshComponent
          └ BoxCollision
  4. Agar sudrash ishlamasa: Box Collision tanlang → Details da Attach / Parent sozlamasi (kamdan-kam kerak) yoki o‘ng tugma → Attach to → Static Mesh.
Majburiy emas, lekin tavsiya. Parallel (aka-uka) qilib qoldirsangiz ham bugungi test ishlaydi. Child qilish — keyinroq odat yaxshi.
6

Collision ni biroz kattalashtirish

Mesh atrofida “qalinroq” chegara

  1. Components da Box Collision ni tanlang.
  2. Details da Shape yoki Box Extent ni toping.
    • Box Extent: masalan X=55, Y=55, Z=55 (default ~32–50 atrofida bo‘lishi mumkin).
    • Yoki Transform → Scale: 1.1 yoki 1.2 (Mesh dan biroz katta).
  3. Maqsad: wireframe (keyinroq Show Collision) Mesh dan biroz tashqariga chiqsin.
  4. Juda katta qilmang (butun xonani bosib olmasin) — 10–20% kattaroq yetarli.
Nima uchun kattaroq? Keyinroq o‘yinchi “E” bosganda Line Trace / Overlap chegara ichiga tushishi osonroq bo‘ladi. Juda qattiq mesh-sized collision ba’zan “tegmay” qoladi.
7

Compile va Save

Har doim odat qiling

  1. Yuqoridagi toolbar da Compile bosing (yoki F7 — versiyaga qarab).
  2. Yashil “checkbox” / xato yo‘qligi — muvaffaqiyat.
  3. Save (Ctrl+S). Asset saqlansin.
  4. Agar Compile qizil xato bersa — Components da Mesh tanlanganini va nomni tekshiring. Bugun script yo‘q, xato kam bo‘ladi.
8

Levelga 2–3 nusxa joylashtirish

Instance lar

  1. Asosiy Level Viewport ga qayting (Blueprint oynasini yopish shart emas — tab almashtiring).
  2. Content Browser dan BP_TestObject ni toping.
  3. Uni Viewport ga sudrab tashlang (drag & drop). Birinchi instance paydo bo‘ladi.
  4. Yana bir-ikkita:
    • Yana drag qiling, yoki
    • Birinchisini tanlab Alt + sudrash (duplicate), yoki
    • Ctrl+W / Duplicate.
  5. Har birini turli joyga qo‘ying — bir-biriga yopishib qolmasin.
Kutiladigan holat: Levelda 2–3 ta bir xil ko‘rinishdagi kub (sizning BP dan). Outliner da BP_TestObject, BP_TestObject2… ko‘rinishi mumkin.
9

Show Collision — chegara ko‘rinsin

Testning eng muhim qismi

  1. Viewport da yuqori menyu: Show (yoki View) → Collision ni yoqing.
    • Ba’zi versiyalarda: Viewport chap yuqori “Lit” yonidagi Show bayroqchalari.
    • Yoki Alt + C (ko‘p loyihalarda Collision toggle).
  2. BP_TestObject instance lar atrofida wireframe (yashil / binafsha chiziqlar) ko‘rinishi kerak.
  3. Wireframe Mesh dan biroz katta bo‘lsa — yaxshi (qadam 6 ishlagan).
  4. Agar umuman ko‘rinmasa:
    • Instance tanlanganmi?
    • Blueprint da Box Collision borligini qayta ochib tekshiring.
    • Compile + Save qilinganmi?
    • Show → Collision haqiqatan ON mi?
10

Transform bilan o‘ynash

Instance larni turlicha qiling

  1. Bitta BP_TestObject ni tanlang.
  2. Details → Transform → Location ni o‘zgartiring (masalan Z ni ko‘tarib “osib qo‘ying”).
  3. Scale ni 0.5 yoki 2 qilib ko‘ring.
  4. Rotation Yaw ni 45° qiling.
  5. Boshqa instance da boshqacha qiymatlar qo‘ying — Blueprint bitta, instance lar farq qilishi mumkin.
Eslatma: Instance dagi Transform — shu joydagi nusxaga tegishli. Blueprint ichidagi Mesh Scale ni o‘zgartirsangiz, yangi joylashtirilganlar ta’sirlanadi; allaqachon override qilingan instance lar ba’zan eski qiymatni saqlaydi.

! Tez-tez uchraydigan xatoliklar va yechimlar

1) Blueprint Class yaratmoqchi bo‘lsam, Actor chiqmayapti

Pick Parent Class oynasida qidiruvga Actor yozing. “All Classes” ni kengaytiring. Common Classes da “Actor” bo‘lishi kerak. Character tanlamang.

2) Static Mesh qo‘shdim, lekin Viewport bo‘sh

Mesh Component tanlangan, lekin Static Mesh asset (Cube) hali None. Details → Static Mesh → Cube / Shape_Cube tanlang. Engine Content yoqilganini tekshiring.

3) Cube umuman topilmayapti

Content Browser → Settings / View Options → Show Engine Content. Keyin qidiruv: Shape_Cube. Yoki Starter Content yoqilgan loyihada boshqa cube assetlar ham bo‘lishi mumkin.

4) Show Collision yoqsam ham wireframe yo‘q

BP da Box Collision borligini ishonch qiling. Compile + Save. Leveldagi instance eskisi bo‘lishi mumkin — o‘chirib qayta drag qiling. Collision Enabled (Query and Physics) ekanligini Details da tekshiring.

5) Levelga tashlasam, hech narsa ko‘rinmaydi

Kamera yerdan uzoqda yoki ichida bo‘lishi mumkin. F (Focus) tugmasi — tanlangan Actor ga fokus. Yoki Outliner dan BP_TestObject ni tanlab, Viewport da F bosing.

6) Components panelini topa olmayapman

Blueprint editor ichidasizmi (Level Viewport emas)? Window → Components. Yoki editor layout ni Default ga qaytaring.

7) Parent/Child sudrash ishlamayapti

Component ni aniq nom ustiga tashlang. Yoki o‘ng tugma → Attach To. Bugun parallel qoldirish ham mumkin — test o‘tadi.

★ Challenge — Point Light (batafsil)

Uchinchi Component: Point Light

Maqsad: obyekt atrofida rangli nur. Component yana bir “qatlam” ekanligini his qilasiz.

  1. BP_TestObject ni oching.
  2. Add Component → Point Light.
  3. Details → Intensity: masalan 3000–8000 (qorong‘i levelda seziladi).
  4. Light Color: qizil yoki ko‘k tanlang (Color picker).
  5. Attenuation Radius: 200–500 (nur qancha uzoqqa yetadi).
  6. Compile, Save. Levelda instance yaqinida rangli yorug‘lik ko‘rinsin.
  7. Ixtiyoriy: Light ni Mesh child qiling — mesh siljisa nur ham ketadi.

? FAQ — o‘qiyotganda chiqadigan savollar

BP_ prefiksi majburiymi?

Majburiy emas, lekin 90 kunlik kursda barcha Blueprint lar BP_ bilan boshlanadi. Keyin Content Browser da topish oson. Odatlaning.

Nima uchun Character emas, Actor?

Character — yurish, capsule, input uchun maxsus. Oddiy “dunyodagi buyum” uchun Actor yetarli va engil. Eshik, quti, generator — Actor.

DefaultSceneRoot ni o‘chirsam bo‘ladimi?

Odatda yo‘q / kerak emas. Ba’zi hollarda Mesh ni root qilishadi. Bugun DefaultSceneRoot ni qoldiring.

Collision ni Mesh dan kichik qilsam nima bo‘ladi?

Tashqi “tegish” qiyinlashadi. Interaction keyinroq noqulay bo‘lishi mumkin. Biroz kattaroq — xavfsizroq.

Play bosib ko‘rsam bo‘ladimi?

Ha. Kublar turganini ko‘rasiz. Lekin bugun yangi mantiq yo‘q — E bosib hech narsa bo‘lmaydi (bu Kun 3–7).

Bir nechta BP_TestObject ni keyin o‘zgartirsam, hammasi yangilanadimi?

Blueprint dagi Component o‘zgarishlari odatda instance larga tarqaladi. Instance da override qilingan qiymatlar (masalan maxsus Scale) saqlanib qolishi mumkin.

Systems papkasidagi BP_Sandbox (Kun 1 challenge) nima bo‘ladi?

U alohida mashq edi. Bugun asosiy e’tibor BP_TestObject. BP_Sandbox ni xohlasangiz xuddi shu usulda Mesh qo‘shib boyitishingiz mumkin — majburiy emas.

★ Professor izohi

Unreal da “narsa” degani deyarli har doim Actor + Components. Bugun siz shu jumlani nafaqat o‘qidingiz — qo‘lda yig‘dingiz.

Ko‘pchilik yangi o‘quvchi darhol Event Graph ga shoshiladi. Siz esa avval suyak tuzilmani to‘g‘ri qo‘ydingiz. Ertaga BeginPlay va Print String yozasiz — lekin Mesh va Collision allaqachon joyida.

Hierarchy ni chalkashtirmang. Har safar yangi Actor ochganda so‘rang: “Ko‘rinish qayerda? Chegara qayerda? Parent kim?” Shu uchta savol 90 kun davomida sizni qutqaradi.

→ Ertaga nima bo‘ladi? (Kun 3)

Kun 3 da BP_TestObject ning Event Graph i ochiladi. Birinchi marta:

  • BeginPlay → Print String (“Salom, BetrayBuilder!”)
  • Boolean variable + Branch
  • Sichqoncha input bilan oddiy mantiq

Bugun yaratgan Actor — ertangi “dasturlash maydoni”. Shu sabab bugun Compile/Save ni unutmang.

Checklist dagi barcha bandlar yashil bo‘lsa — Kun 2 yopildi. Dam oling yoki Challenge (Point Light) ni qo‘shing.
