Bugungi aniq maqsad

Inventory’dagi item’larni haqiqiy gameplay maqsadida ishlatish: Key → Door, Battery → Generator, Medkit → Health. HasItem funksiyasi va RequiredKeyID orqali qulflangan eshik mantig‘i.

01 Nima uchun bu kun muhim?

Shu kungacha item’lar “to‘planadigan narsalar” edi. O‘yinchi ularni oladi, Inventory to‘ladi — lekin maqsad yo‘q edi. Bugun item’lar o‘yin dunyosiga ta’sir qila boshlaydi.

Bu — progression va puzzle dizaynining asosi. Qulflangan eshik, generator, sog‘liq — bular o‘yinchini xarita bo‘ylab yurishga, qaror qabul qilishga majbur qiladi.

Professor eslatmasi

Yaxshi o‘yin dizayni: “olish” va “ishlatish” o‘rtasida masofa bor. Kalitni topdingiz — lekin eshik boshqa xonada. Battery oldingiz — generator uzoqda. Bu masofa o‘yinchi tajribasini boyitadi. Bugun shu bog‘lanishni kodlaymiz.

02 Nazariya — Consumable vs Key-type

Key-type item

Belgilangan maqsad uchun. Ba’zan qayta ishlatiladi.

  • Key — eshik ochadi
  • Keycard — maxsus eshik
  • Odatda Inventory’da qoladi (hozircha)
Consumable item

Ishlatilgach yo‘qoladi yoki ta’sir qiladi.

  • Medkit — Health +30
  • Battery — Generator’ga qo‘yiladi
  • Keyinchalik Inventory’dan olib tashlanadi

Bugun asosiy e’tibor: tekshirish va ta’sir. Item’ni Inventory’dan olib tashlash (Remove) — ertaga (Day 34) bilan birga keladi. Hozircha “bor-yo‘q” ni tekshiramiz va natijani qo‘llaymiz.

03 HasItem(ItemID) — markaziy funksiya

Bu funksiya InventoryArray ichida berilgan ItemID bor-yo‘qligini tekshiradi. Boolean qaytaradi. Keyinroq Door, Generator, boshqa tizimlar shu funksiyadan foydalanadi. 

// BP_Player → Function: HasItem
// Input:  ItemID (Name)
// Output: Return Value (Boolean)

1. For Each Loop (InventoryArray)
2. Loop Body:
   - Break S_ItemData (Array Element)
   - Branch: Break.ItemID == Input ItemID
     - True → Return true  (va Loop'ni to'xtatish mumkin)
3. Completed (hech narsa topilmasa):
   - Return false

Optimallashtirish: Topilganda Loop’dan chiqish uchun Break (For Each Loop ning) yoki alohida Boolean flag ishlatishingiz mumkin. Kichik Array (max 8) uchun oddiy For Each ham yetarli.

05 Battery → Generator

Generator (yoki BP_Generator) Interact qilinganda:

  1. Player.HasItem(“Battery”) tekshiriladi
  2. True bo‘lsa — “Generator to‘ldirildi” Print String (yoki haqiqiy mantiq: IsPowered = true)
  3. False bo‘lsa — “Battery kerak” xabari

Hozircha sodda versiya yetarli. Keyinchalik (Sabotage tizimida) Generator muhimroq rol o‘ynaydi.

06 Medkit → Health +30

Medkit’ni ishlatish uchun ikki yo‘l mumkin:

  • A) Inventory UI’dan tanlab “Use” (UI hali yo‘q — Day 66)
  • B) Hozircha: maxsus input yoki test uchun funksiya — HasItem(“Medkit”) bo‘lsa Health += 30

Eng sodda test: BP_Player da vaqtinchalik tugma (masalan H) bosilganda HasItem(Medkit) tekshirib, Health ni oshirish. Yoki Medkit item’ning o‘zini “use on self” qilib qo‘yish.

Health o‘zgarishi Day 13’da yaratilgan Health / MaxHealth variable’lariga bog‘liq. Clamp qiling: Health 0 dan MaxHealth gacha.

09 Keng tarqalgan xatolar

1. HasItem doim false qaytaradi

InventoryArray ga item qo‘shilganini tekshiring (Day 31). ItemID solishtirishda Name tipida ekaniga ishonch hosil qiling (String bilan aralashtirmang). Data Table Row Name va Inventory’dagi ItemID bir xilmi?

2. Qulflangan eshik hammaniki uchun ochiq

RequiredKeyID Level instance’da to‘g‘ri qo‘yilganini tekshiring. Default None bo‘lsa — eshik oddiy ishlaydi.

3. Cast to BP_Player muvaffaqiyatsiz

Interact Instigator sifatida Player uzatilayotganini tekshiring (Day 30 dagi kabi).

4. Health MaxHealth dan oshib ketadi

Clamp (Float) ishlating: NewHealth = Clamp(Health + 30, 0, MaxHealth).

★ Professor izohi

Bugun siz query yozdingiz: “Inventory’da bu narsa bormi?”. Bu oddiy savol, lekin butun o‘yin mantiqi shu savollarga tayanadi.

HasItem — qayta ishlatiladigan, toza interfeys. Eshik, generator, kelajakdagi quest — hammasi shu bitta funksiyaga murojaat qiladi. Yaxshi dasturchi shunday qiladi: umumiy savolni bir marta javoblaydi, keyin hamma joyda ishlatadi.

→ Keyingi kun — Day 34: Drop Item

Ertaga item’ni Inventory’dan chiqarib, dunyoga qaytaramiz (Drop). Shu bilan birga Consumable’larni ishlatgandan keyin olib tashlash ham qo‘shilishi mumkin. Pickup ↔ Inventory ↔ Use/Drop zanjiri to‘liq yopiladi.
