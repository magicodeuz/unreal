Stage 3 · Kun 16 · Universal Interaction shartnomasi

BPI_Interact

Kun 5 dagi Interface g‘oyasini real tizimga aylantirasiz. Door, Button, Light, Computer — hammasi bitta shartnoma: Interact, GetInteractionText, CanInteract.

🎯 Kun maqsadi

Kun oxirida:

  • → BPI_Interact asset — uchta funksiya imzosi
  • → BP_TestObject interfeysni implement qiladi (Print sinovi)
  • → BP_Player: Line Trace focus + E → Interface Message Interact
  • → CanInteract false bo‘lsa Interact chaqirilmaydi
  • → Cast To BP_Door yozilmaydi — bitta Message hammaga

Bugun qilmang: Haqiqiy eshik animatsiyasi, UI widget “Press E”, yangi 10 xil interactable. Faqat shartnoma + bitta sinov obyekti + Player chaqiruvi.

Nima uchun uzun dars? Bu interface butun 90 kunlik kursda qayta ishlatiladi. Imzo noto‘g‘ri bo‘lsa — keyin har bir Door/Button ni qayta yozasiz. Bir marta to‘g‘ri qo‘ying.

5 Kun 5 eslatmasi — nima o‘zgardi?

Kun 5 da BPI_TestInterface va Cast vs Interface farqini ko‘rdingiz. Bugun:

  • Interface nomi professional: BPI_Interact
  • Faqat “OnActivate Print” emas — uchta aniq majburiyat
  • Chaqiruv manbai: random reference emas, Line Trace focus (Kun 15)
  • Input: oddiy Keyboard emas, IA_Interact

Agar Kun 5 dagi BPI_TestInterface hali bor bo‘lsa — chalkashtirmang. Yangi BPI_Interact yarating; eski test interface’ni keyin o‘chirishingiz mumkin.

? Nima uchun bitta BPI_Interact?

O‘yinda interaktiv narsalar ko‘p:

  • Eshik ochish / yopish
  • Generator yoqish
  • Task panel
  • Item olish
  • Light switch / saboteur sabotage

Agar Player’da har biri uchun Cast To BP_Door, Cast To BP_Generator… bo‘lsa — har yangi obyekt Player kodini ochishni talab qiladi. Bu tight coupling (Kun 5).

BPI_Interact: Player faqat “Interact deb ayt” deydi. Har obyekt o‘zi biladi nima qilishni. Yangi tip = yangi Blueprint + implement — Player o‘zgarmaydi.

📜 Shartnoma — uchta funksiya

Interact

Amalni bajaradi. Input: kim bosgani (Instigator).

Interact (Instigator: Actor)
  // Door: open/close
  // Button: toggle
  // TestObject: Print String

Return shart emas (void). Side-effect’li “event” uslubidagi funksiya.

GetInteractionText → String

UI’da ko‘rsatiladigan matn. Masalan: "Eshikni ochish [E]", "Generatorni yoqish".

Bugun Print yoki log uchun; Kun ~65 da widget shu string’ni o‘qiydi. Hozir implement qilib qo‘ying — keyin UI oson.

CanInteract → Boolean

Hozir interact mumkinmi? Qulflangan eshik → false. Allaqachon olingan item → false. Masofa / role keyinroq.

Player E bosganda avval CanInteract so‘raydi; false bo‘lsa Interact chaqirmaydi (challenge + asosiy qoida).

👤 Instigator — nima uchun kerak?

Instigator = “kim interact qildi”. Odatda BP_Player (yoki Pawn).

  • Item olish → inventory shu o‘yinchiniki
  • Task → qaysi player progress
  • Multiplayer → server kim ekanini biladi
  • Eshik → ba’zan faqat certain role ochadi (Instigator dan role so‘rash)

Interface’da Input pin: Instigator (Actor yoki Pawn). Player Message chaqirganda Self ni uzatadi.

2

Uchta funksiya imzosi

Taxminiy vaqt: 20–25 daqiqa · eng muhim qism

2.1 Interact

Functions → Add → Name: Interact

Details → Inputs → + :

  • Name: Instigator
  • Type: Actor (Object Reference) — yoki Pawn, lekin Actor kengroq

Outputs: bo‘sh (void).

Ba’zi versiyalarda funksiya nomi “Interact” reserved emas — ishlaydi. Agar conflict bo‘lsa: OnInteract.

2.2 GetInteractionText

Yangi funksiya: GetInteractionText

Inputs: bo‘sh (yoki ixtiyoriy Instigator — matn role’ga qarab o‘zgarishi mumkin; bugun bo‘sh).

Outputs → + :

  • Name: Return Value (yoki Text)
  • Type: String

Pure? Interface funksiyalarida “Pure” ba’zan cheklangan. Oddiy function qoldiring. Get matn — side-effect’siz bo‘lishi kerak (faqat string qaytarish).

2.3 CanInteract

Yangi funksiya: CanInteract

Inputs: ixtiyoriy Instigator (Actor) — “shu o‘yinchi uchun mumkinmi?”

Bugun soddalashtirish: Inputs bo‘sh, Output Boolean.

Output: Return Value — Boolean.

Compile / Save BPI_Interact.

Tekshirish: Interface’da 3 ta funksiya ko‘rinsin. Ichida node graph yo‘q — to‘g‘ri.

Challenge uchun: Boolean variable bIsLocked → Return NOT bIsLocked. Default false → CanInteract true.

BP_Player — E bosilganda Message

Taxminiy vaqt: 25–35 daqiqa

4.1 IA_Interact event

BP_Player Event Graph → IA_Interact

Kun 6 dagi Print bo‘lsa — o‘rniga haqiqiy mantiq. Trigger: Started (bir marta bosish) yaxshiroq — hold qayta-qayta Interact qilmasin.

4.2 Focus bormi?

Started → Branch (bHasFocus) yoki Is Valid (CurrentFocusedActor).

False → hech narsa (yoki debug Print “Nothing in focus”).

4.3 Interact Message

Qidiruv: Interact → Interact (BPI_Interact) Message variantini tanlang.

Target = CurrentFocusedActor

Instigator = Self (Get a reference to self)

Cast yo‘q: Target to‘g‘ridan Actor. Message implement qilmagan Actor’da odatda jim o‘tadi — shuning uchun Does Implement ham qo‘shamiz.

Does Implement Interface

Taxminiy vaqt: 10 daqiqa

6.1 Nima uchun?

Line Trace har qanday Actor’ga tegishi mumkin: devor, pol, prop. Ularga Interact Message yuborish — odatda zararsiz, lekin CanInteract chaqiruvi ham “bo‘sh” ishlashi mumkin.

Does Implement Interface: Target = CurrentFocusedActor, Interface Class = BPI_Interact → Boolean.

True bo‘lsa — bu “bizning” interactable. False — e’tibor bermang (yoki debug rangini kulrang qiling).

Focus o‘zgarganda ham shu tekshiruv UI “Press E” ni faqat haqiqiy target’da ko‘rsatadi (keyinroq).

GetInteractionText — hozircha sinov

Taxminiy vaqt: 10 daqiqa

7.1 Focus o‘zgarganda Print

Ixtiyoriy lekin foydali: Tick yoki focus change da, agar Does Implement:

GetInteractionText (Message) → Print String (qisqa duration).

Ekranda “Test obyekt [E]” ko‘rinsa — UI uchun tayyor kanal ochildi.

Spam bo‘lmasin deb faqat focus change da chaqiring (oldingi Actor ≠ yangi).

Yomon (qilmang):

Focus → Cast To BP_Door → …

Maxsus logika kerak bo‘lsa (faqat Door ichida) — u Door Blueprint’ining Interact implementatsiyasida yashaydi, Player’da emas.

★

Challenge — CanInteract false

  1. BP_TestObject’da bCanBeUsed Boolean (default true).
  2. CanInteract → Return bCanBeUsed.
  3. Interact ichida: muvaffaqiyatli ishlagach bCanBeUsed = false (bir marta ishlatiladigan “tugma”).
  4. Player’da CanInteract Branch majburiy.
  5. Test: birinchi E — Print; ikkinchi E — jim (yoki “Can't”).

Bu keyingi “qulflangan eshik” va “tugallangan task” modeli.

? FAQ

Interface va Component farqi?
Interface — “qila olaman” shartnomasi, kod yo‘q. Component — qayta ishlatiladigan mantiq + state. Ko‘pincha: Actor BPI_Interact implement qiladi; og‘ir mantiq component’da bo‘lishi mumkin.
Nima uchun GetInteractionText alohida?
UI har frame yoki focus change da matn so‘raydi; Interact bosilganda bir marta. Ajratilgan funksiya — matnni interact mantiqidan ajratadi (ochiq/yopiq eshik matni o‘zgaradi, CanInteract ham).
Message vs Event Dispatcher?
Dispatcher — “eshtuvchilarga e’lon”. Interface Message — “shu obyektning shartnomasidagi funksiyani chaqir”. Interact uchun Message to‘g‘ri vosita.
Blueprint Native Interface / C++?
Keyinroq C++ ga o‘tkazish mumkin. Hozir toza Blueprint Interface yetarli.
Bir Actor ikkita interface implement qila oladimi?
Ha. Masalan BPI_Interact + BPI_Damageable. Har biri alohida shartnoma.

◇ Dizayn eslatmalari — keyingi kunlar uchun

1. Matn dinamikasi

Eshik yopiq: “Ochish [E]”. Ochiq: “Yopish [E]”. GetInteractionText ichida Branch (bIsOpen) — UI har safar yangi matn oladi.

2. CanInteract vs masofa

Masofa odatda TraceDistance bilan allaqachon cheklangan. CanInteract — holat (qulf, cooldown, inventory talabi), masofa emas.

3. Hold to interact

Hozir Started = bir marta. Keyin: hold 1.5 s → progress bar. Interface’ga HoldDuration qo‘shish o‘rniga alohida “channel” yoki component — imzoni buzmaslik uchun.

4. Multiplayer

Interact ko‘pincha Server RPC. Interface Message client’da chaqiriladi → ichida “Server_Interact”. Hozir single-player; architecture shu yo‘lga ochiq.

5. Outline / highlight

Focus + DoesImplement true → Custom Depth / outline. Trace kunida focus bor; bugun interface bilamiz — highlight faqat interactable’larga.

! Eng ko‘p uchraydigan xatolar

1. Interface’ga mantiq yozishga urinish

BPI ichida Event Graph yo‘q. Mantiq faqat implement qiluvchi BP’da.

2. Message o‘rniga “Call function on BP_TestObject”

Bu yana Cast talab qiladi. Message ishlating.

3. Implement qilgach Compile qilmaslik

Does Implement false qaytishi mumkin. Har doim Compile + Save.

4. Focus Actor’ni “promoted” hard-reference qilib qo‘yish

Har tick yangilanadi. Levelda fixed reference emas.

5. CanInteract’ni faqat obyektda yozib, Player’da tekshirmaslik

Obyekt true/false qaytarishi kerak; Player Branch qilishi kerak. Ikkalasi ham.
