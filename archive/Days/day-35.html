Bugungi aniq maqsad

To‘liq Pick Up → Inventory → Use → Drop zanjirini yaxlit sinash. Yangi feature yo‘q — faqat integration testing. Barcha to‘rt amal ma’lumot yo‘qotmasdan, xatosiz ishlashi kerak. Bu Stage 6 (Objective / Gameplay Loop) uchun mustahkam asos.

01 Nima uchun Integration Test?

Har bir kun alohida ishlagan. Lekin tizimlar birga ishlaganda yangi xatolar chiqadi: index siljishi, ItemID yo‘qolishi, BeginPlay tartibi, Cast muvaffaqiyatsizligi…

Integration test — bu “hammasi birga” sinovi. AAA studiyalarda feature freeze dan oldin shunday kunlar bo‘ladi: yangi narsa yozilmaydi, faqat zanjir tekshiriladi va mustahkamlanadi.

Professor eslatmasi

Yaxshi dasturchi “ishlayapti” deb o‘ylamaydi — u isbotlaydi. Bugun siz isbotlayapsiz: item olinadi, saqlanadi, ishlatiladi, tashlanadi, yana olinadi. Ma’lumot yo‘qolmaydi. Limit ishlaydi. Eshik kalit bilan ochiladi. Bu isbot — Milestone 5.

04 Test ssenariylari — batafsil

A

Key zanjiri

Olish → saqlash → eshik ochish

  1. Key’ni oling — Print “Olindi: … | X/8”
  2. Inventory Length 1 ga oshganini tekshiring
  3. Qulflangan eshikni kalitsiz ochib bo‘lmasligini tasdiqlang
  4. Kalit bilan oching — eshik ochiladi
  5. Key Inventory’da qolishi yoki (agar reja shunday bo‘lsa) olib tashlanishi — rejaga mos
B

Battery → Generator

  1. Battery oling
  2. Generator’ga Interact — effekt (Print / IsPowered)
  3. Agar Consume qilgan bo‘lsangiz — Inventory’dan yo‘qolganini tekshiring
C

Medkit → Health

  1. Avval Health ni pasaytiring (yoki past qiymatdan boshlang)
  2. Medkit oling → ishlating
  3. Health +30 (Clamp MaxHealth gacha) ekanini tasdiqlang
D

Drop ↔ Pickup aylanmasi

  1. Item oling → Drop (G) → oldinda paydo bo‘lsin
  2. Yana oling — ItemID va nom o‘zgarmagan bo‘lsin
  3. Bir necha marta takrorlang — barqaror ishlashi kerak
E

Hajm limiti (8)

  1. 8 ta item oling — hammasi qabul qilinsin
  2. 9-chi — “Inventory to‘la!” va Actor yo‘qolmasin
  3. Bitta Drop qiling → yana bitta oling — ishlashi kerak

07 Integration paytida tipik xatolar

Drop qilingan item nomi “None” yoki bo‘sh

ItemID Spawn’da o‘rnatilmagan yoki BeginPlay Data Table’dan o‘qishdan oldin Interaction matni so‘ralgan. ItemID ni Expose on Spawn qilib bering; GetInteractionText da null check qo‘ying.

8 tadan keyin ham qo‘shilaveradi

AddItemToInventory dagi Branch shartini tekshiring. BP_Item faqat true qaytsa Destroy qilishi kerak.

HasItem true, lekin eshik ochilmaydi

RequiredKeyID va Inventory’dagi ItemID bir xilmi (katta-kichik harf)? PrintInventory bilan solishtiring.

Drop dan keyin Array buziladi

Remove dan oldin Get qiling. Index ni saqlab, keyin Remove qiling. Loop ichida Remove qilmang.

★ Challenge — PrintInventory

Debug vositasi yozing

Inventory holatini (barcha item nomlari va indekslari) bitta funksiya orqali to‘liq Print String qilib chiqaradigan vosita. Yuqoridagi PrintInventory shablonidan foydalaning. Ixtiyoriy: Pickup va Drop dan keyin avtomatik chaqiring.

★ Professor izohi

Milestone — bu faqat “tugadi” degan yorliq emas. Bu ishonch nuqtasi. Bundan keyin Objective System, Sabotage, multiplayer — hammasi shu Inventory’ga tayanadi. Agar bugun zanjir mustahkam bo‘lsa, keyingi 50 kun osonroq kechadi.

Siz 7 kunda: parent-child hierarchy, interface, array of struct, data table, query funksiyasi, spawn/destroy aylanmasi — bularning barchasini bir tizimga birlashtirdingiz. Bu junior dan mid-level ga o‘tishning aniq belgisi. Tabriklayman.
