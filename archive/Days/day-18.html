Stage 3 · Kun 18 · Cross-actor communication

Button

Player → Button → Door. Bitta Actor ikkinchisiga Interface orqali buyruq beradi — Sabotage / remote control asosi.

🎯 Kun maqsadi

  • → BP_Button — kichik mesh + BPI_Interact
  • → TargetDoor — Instance Editable Actor reference
  • → Button Interact → TargetDoor ga Interact Message
  • → Levelda Button Details dan Door tanlash
  • → E Button’da → Door ochiladi/yopiladi (Button o‘zi ochilmaydi)
  • → Player kodi yana o‘zgarmaydi

Bugun qilmang: Ko‘p target (faqat challenge), UI, kalit, network. Bitta Button → bitta Door.

Nima uchun muhim? “Uzoqdan ta’sir” — generator, alarm, sabotage panel hammasi shu pattern: local interact → boshqa Actor’ga Message.

? Nima uchun alohida Button?

Kun 17 da Player to‘g‘ridan Door’ga E bosardi. Bu har doim kerak emas: eshik yuqorida, tugma pastda; yoki “xavfsizlik paneli” eshikdan uzoqda.

Button — proxy: o‘yinchi unga tegadi, u boshqa obyektni ishga tushiradi. Dizayn: xona layout’i erkinlashadi.

Betray Builder’da saboteur tugmasi yoritishni o‘chirishi, yoki crew button eshikni ochishi — bir xil texnika.

Player Door’ni bilmaydi. Button Door class’ini bilmaydi — faqat “BPI_Interact implement qilgan Actor”. Door o‘z Timeline’ini biladi.

🔗 Actor Reference nima?

Variable tipi Actor (Object Reference) — “shu leveldagi aniq nusxaga ko‘rsatkich”.

Instance Editable bo‘lsa, levelda Button tanlab Details’dan boshqa Actor’ni pick qilasiz (eyedropper / dropdown).

Bu hardcode emas: bir Button A eshik, ikkinchi Button B eshik — bir xil BP_Button class, turli reference.

Soft vs hard: Hozir oddiy Object Reference yetarli. Soft reference — asset stream / katta loyiha; keyinroq.

Tipni BP_Door qilib cheklash mumkin (faqat Door pick). Interface ruhida yaxshiroq: tip Actor yoki interface implement qiluvchi — lekin UE da “interface type variable” cheklangan; praktika: Actor + Is Valid + Message (Message implement qilmasa jim).

📖 Interface’ning haqiqiy kuchi

Agar Button ichida Cast To BP_Door bo‘lsa — keyin “Button light’ni ham yoqsin” deganingizda yangi Cast. Interface Message: TargetDoor o‘rniga TargetActor — eshik, chiroq, alarm hammasi Interact implement qilsa ishlaydi.

Bugun nom TargetDoor — o‘qish uchun aniq. Ichki mantiqda Message orqali chaqirasiz, Cast shart emas.

5

Interact — Message yuborish

Taxminiy vaqt: 20–25 daqiqa

5.1 Event Interact 
Event Interact (Instigator)
  → Is Valid TargetDoor?
       False → Print "Button: TargetDoor not set"
               return
  → Interact (BPI_Interact Message)
       Target = TargetDoor
       Instigator = Instigator   // Player’ni uzating
  → (ixtiyoriy) Print "Button pressed"

Qidiruvda Message variantini tanlang, “Call function on BP_Door” emas.

5.2 CanInteract target’da?

Yaxshi odat: avval TargetDoor ga CanInteract Message, True bo‘lsa Interact.

Door animatsiya paytida CanInteract false — Button bosilsa ham Door rad etadi. Izchil.

7.1 Joylashtirish

  2. BP_Button ni eshik yoniga yoki boshqa xonaga qo‘ying.

8

Instigator — kim bosgan?

Dizayn tanlovi

Player Button’ga Interact yuboradi, Instigator = Player. Button Door’ga yuborayotganda:

  • Instigator = kelgan Instigator — Door “o‘yinchi bosdi” deb biladi (inventory, role)
  • Instigator = Button Self — Door “tugma bosdi” deb biladi

Ko‘pincha Player’ni uzatish to‘g‘ri. Door keyinroq “faqat crew ochadi” desa Instigator’dan role oladi.

? FAQ

Nima uchun Door’ni Button child qilmaymiz?
Parent-child transform bog‘laydi. Eshik va tugma turli joyda bo‘lishi kerak — reference erkinroq.
Event Dispatcher yaxshiroq emasmi?
Dispatcher “e’lon”: kim tinglasa eshitadi. Bu yerda aniq target bor — Message to‘g‘ridan. Dispatcher ko‘p listener uchun (UI, achievement).
Blueprint Interface o‘rniga to‘g‘ridan Open chaqirish?
Open faqat Door’da. Message — kelajakdagi Light/Alarm uchun bir xil kanal.
Multiplayer’da reference?
Levelda joylashtirilgan Actor’lar odatda serverda mavjud; reference replicate qilinishi kerak bo‘lishi mumkin. Hozir single-player.
