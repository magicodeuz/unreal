Line Trace

Interaction System’ning yuragi: har freym kameradan chiziq chiqarib, o‘yinchi nimaga qarab turganini aniqlaysiz. Eshik, tugma, item — hammasi shu “ko‘z” orqali topiladi.

🎯 Kun maqsadi

Kun oxirida sizda quyidagilar bo‘lishi kerak:

  • → Kameradan Line Trace (masofa ~300 unit)
  • → CurrentFocusedActor — hozir nishonga olingan Actor (yoki null)
  • → bHasFocus yoki Hit? boolean — qulay Branch uchun
  • → Draw Debug Line — editor’da ko‘rinadigan chiziq
  • → Print orqali Hit Actor nomi (debug)
  • → O‘zingizni (Self) ignore qilish

Bugun qilmang: Interface Message / OnInteract chaqirish (Kun 16), UI prompt “Press E” (Keyinchalik), multiplayer replication. Faqat “ko‘rish” qatlami.

Nima uchun bu kun uzun? Stage 3 dagi barcha interact (eshik, generator, ovoz, saboteur) shu trace natijasiga tayanadi. Bu yerda chalkashlik keyin 20 kunni “tuzatish”ga aylantiradi. Shuning uchun Start/End, Channel, Hit, Debug — hammasi batafsil.

📖 Nazariya — ray nima qiladi?

Line Trace (raycast): fazoda nuqtadan (Start) ikkinchi nuqtaga (End) math chiziq. Engine shu chiziq yo‘lida birinchi “to‘siq”ni qidiradi (collision sozlamalariga qarab).

Topilsa → blocking hit (yoki siz sozlagan javob). Topilmasa → hit yo‘q, Focus = none. 

Start  ●━━━━━━━━━━━━━━━━●  End
              │
              └── birinchi urilgan sirt = Hit
                  Hit Actor, Hit Location, Distance…

Line Trace By Channel — eng ko‘p ishlatiladigan variant. “Visibility” yoki “Camera” channel bo‘yicha: bu channel’da block qiluvchi obyektlar “ko‘rinadi”.

Boshqa variantlar (bilib qo‘ying, bugun majburiy emas):

  • Line Trace By Object Type — faqat ma’lum object type (WorldStatic, Pawn…)
  • Line Trace By Profile — collision profile nomi
  • Sphere Trace — qalin “truba”, kichik tugmalarni osonroq ushlaydi
  • Multi Line Trace — bir nechta hit (devor orqasidagini ham)

击 Hit Result — ichida nima bor?

Break Hit Result node’i struct’ni ochadi. Eng muhimlari:

Maydon Ma’no
Blocking Hit Umulan hit bormi? (bool)
Hit Actor Urilgan Actor reference
Hit Component Qaysi component (Mesh, Collision…)
Location / Impact Point Dunyo koordinatasida nuqta
Normal Sirt normali (qaytarish, decal)
Distance Start’dan hit’gacha masofa
Phys Material Keyinroq footstep / impact

Bugun asosan: Blocking Hit? + Hit Actor. Qolganlari keyin (masalan interact nuqtasida VFX).

📡 Trace Channel — Visibility va boshqalar

Har bir collision object “qaysi channel’da block / overlap / ignore” deb sozlanadi. Trace ham channel tanlaydi: “shu channel’da block qilganlar menga hit”.

  • Visibility — odatiy tanlov: ko‘rinadigan world geometry va ko‘p mesh’lar
  • Camera — ba’zan SpringArm o‘zi ishlatadi; interact uchun ham ishlashi mumkin
  • Custom channel (keyinroq) — faqat “Interactable” object’lar

Agar eshikning collision’i Visibility’da Ignore bo‘lsa — trace uni “ko‘rmaydi”. BP_TestObject / Static Mesh default odatda block qiladi. Muammo bo‘lsa: Component → Collision → Trace Responses → Visibility = Block.

Pawn / Character: Boshqa o‘yinchiga trace tegishi yoki tegmasligi — design qarori. Hozircha default qoldiring; keyin “o‘yinchiga interact yo‘q” deb ignore list’ga qo‘shish mumkin.

📍 Start va End — qayerdan qayerga?

Tavsiya (third person):

  • Start = Camera world location (Get Camera Location yoki Camera component Get World Location)
  • End = Start + (Camera Forward Vector × TraceDistance)

Nima uchun kamera, character og‘zi emas? Chunki o‘yinchi ekranda nima ko‘rsa, shunga E bosadi. Crosshair markazi ≈ kamera forward.

TraceDistance = 300 — Kun 8 capsule / interakt masofasi bilan mos. Juda uzun (2000) — devor orqasidagi eshikni “ushlab” qo‘yishi mumkin (agar multi-hit emas, birinchi hit devor bo‘ladi). Juda qisqa (100) — yaqin eshik ham yetmaydi. 

CameraLoc = Get Camera Location
Forward   = Get Camera Forward Vector   // unit vector
End       = CameraLoc + (Forward * TraceDistance)

Alternative: Player view point (Get Player View Point) — Controller dan Location + Rotation birga. Ikkalasi ham to‘g‘ri; Camera component aniqroq “sizning” SpringArm kamerangiz.

Usul A — to‘g‘ridan BP_Player Event Graph (bugun tavsiya)

Tez, o‘rganish oson, hamma narsa bir joyda. Stage 3 boshida yetarli.

Usul B — BPC_Interaction (Actor Component)

Bugun: BP_Player ichida yozamiz. Keyin refactor qilish mumkin — mantiq o‘zgarmaydi, faqat joyi.

1

Variable’larni yaratish

Taxminiy vaqt: 10–15 daqiqa

1.1 CurrentFocusedActor

BP_Player → My Blueprint → Variables → +

  • Name: CurrentFocusedActor
  • Type: Object Reference → Actor (yoki soft Object)
  • Default: None
  • Category: Interaction

Bu har tick yangilanadi: “hozir nishondagi Actor”.

1.2 TraceDistance va bHasFocus
  • TraceDistance — Float — default 300 — Category Interaction|Tuning — Instance Editable
  • bHasFocus — Boolean — default false — “hit bormi?” tezkor Branch
  • bDrawInteractionDebug — Boolean — default true (dev) — keyin false

Compile. Category “Interaction” Key 16 da Interface bilan birga to‘ladi.

2

Kamera Start va End hisoblash

Taxminiy vaqt: 20–25 daqiqa

2.1 Event Tick boshi

Mavjud Tick (stamina, camera Z) dan keyin yoki oldin alohida “Interaction Trace” bloki qo‘shing. Izoh (Comment box): // Interaction Line Trace

Chalkashmaslik uchun Comment ichiga yig‘ing — Keyin o‘qish oson.

2.2 Start = Camera location

Usul 1: Components’dan Camera’ni graph’ga tashlang → Get World Location

Usul 2: Get Player Camera Manager → Get Camera Location

Usul 3: Get Actor Eyes View Point (Pawn) — Location + Rotation chiqadi

Third person uchun Usul 1 yoki 2 aniqroq “ekran markazi”.

2.3 End = Start + Forward × Distance
  1. Camera → Get Forward Vector (World)
  2. Forward × TraceDistance (vector * float)
  3. Start + natija (vector + vector) = End

Xato: Actor Forward ishlatish — tana boshqa tomonga, kamera boshqa tomonga (third person). Har doim kamera forward.

3

Line Trace By Channel

Taxminiy vaqt: 20 daqiqa

3.1 Node qo‘shish

O‘ng sichqoncha → Line Trace By Channel

Pinlar:

  • Start → kamera location
  • End → hisoblangan End
  • Trace Channel → Visibility
  • Trace Complex — odatda false (simple collision yetarli, tezroq)
  • Actors to Ignore — keyingi qadam
  • Draw Debug Type — For Duration yoki None (debug flag bilan)
  • Ignore Self — ba’zi node’larda alohida bool (true qiling)

Return Value (bool) = hit bormi. Out Hit = Hit Result struct.

3.2 Draw Debug Type (vaqtincha)

Hozircha For Duration, Duration 0.1 yoki 0 — har frame chiziladi. Rang: yashil (keyin challenge).

Production’da None + faqat bDrawInteractionDebug true bo‘lganda alohida Draw Debug Line.

4

Break Hit Result va Focus saqlash

Taxminiy vaqt: 15–20 daqiqa

4.1 Branch

Line Trace Return Value → Branch Condition.

True:

  1. Out Hit → Break Hit Result
  2. Hit Actor → Set CurrentFocusedActor
  3. Set bHasFocus = true

False:

  1. Set CurrentFocusedActor = None (Leave empty / clear)
  2. Set bHasFocus = false

Muhim: Har tick False bo‘lganda None qiling. Aks holda eski eshik “focus”da qolib ketadi — E uzoqdan ishlaydi (bug).

5

Draw Debug Line (tashqi, nazoratli)

Taxminiy vaqt: 15 daqiqa

5.1 Alohida debug chizish

Branch bDrawInteractionDebug:

True → Draw Debug Line (Start, End, Color, Thickness 1, Duration 0)

Yoki Hit Location’gacha chizing (qisqa chiziq aniqroq).

Line Trace ichidagi Draw Debug Type ni None qilib, faqat shu orqali boshqarish — toza.

Challenge tayyorgarligi: Color = bHasFocus ? Green : Red (Select Color / Branch ikki Draw).

6

Print Actor nomi (vaqtincha)

Taxminiy vaqt: 10 daqiqa

6.1 Spam’siz print

Har tick Print — ekran to‘ladi. Yaxshiroq:

  • Faqat focus o‘zgarganda print (oldingi Focus ≠ yangi Focus)
  • Yoki 0.5 s Timer
  • Yoki faqat bDrawInteractionDebug && bHasFocus

Hit Actor → Get Display Name → Print String.

Ishonch hosil qilgach — Print’ni o‘chiring yoki debug flag orqasiga yashiring.

Make Array → element Self (Get a reference to self).

Keyinroq: egar / held item ham ignore list’ga.

8

Tick va performance — bilib qo‘ying

O‘qish · majburiy optimizatsiya emas

Bitta Line Trace har frame — oddiy o‘yin uchun arzon. 100 o‘yinchi serverda har biri trace — boshqa suhbat (multiplayer’da odatda client prediction + server validate).

Keyinroq optimizatsiya variantlari:

  • Har 2–3 frame’da bir (counter)
  • Faqat “interact mode” da trace
  • Masofa qisqaroq indoor

Bugun har tick qoldiring — to‘g‘rilik muhimroq.

10

Troubleshooting

Muammo → tekshirish ro‘yxati

Hech qachon hit yo‘q

  • End to‘g‘ri hisoblanganmi? (Draw Debug ko‘rinadimi?)
  • TraceDistance juda kichik emasmi?
  • Obyekt collision yoqilganmi? (No Collision bo‘lsa — ko‘rinmaydi)
  • Visibility channel Block?
  • Complex vs Simple — mesh’da simple collision bormi?

Doimo o‘zingizga hit

  • Ignore Self / Actors to Ignore Self
  • Start ni biroz forward’ga siljiting (kamera ichida mesh)

Debug chiziq yo‘q

  • Show → Developer → … yoki oddiygina Draw Debug ishlaydi PIE da
  • Duration 0 + har tick
  • bDrawInteractionDebug true

Focus eski obyektda qolib ketadi

  • False tarmoqda CurrentFocusedActor = None

Chiziq noto‘g‘ri tomonga

  • Camera Forward, not Actor Forward
  • Control rotation vs mesh orientation
★

Challenge — rangli debug

Draw Debug Line rangini bHasFocus ga bog‘lang:

  • Yashil — biror Actor nishonda
  • Qizil — bo‘sh / osmon / hit yo‘q

Select node yoki ikki xil Draw Branch. Bu keyin “interactablemi?” tekshiruvi uchun ham foydali model (yashil = interface bor, sariq = oddiy mesh…).

★ Bonus — ixtiyoriy chuqurlashtirish

B1 Sphere Trace By Channel

Radius 10–20 — kichik tugmalarni osonroq “ushlash”. Line o‘rniga sinab ko‘ring.

B2 Focus changed event

Oldingi Actor ≠ yangi → Custom Event OnFocusChanged (NewActor). UI va outline shu yerda.

B3 BPC_Interaction component

Trace mantiqini component’ga ko‘chirish — Character toza qoladi. Kun 16 dan oldin yoki keyin.

B4 Distance check

Hit Distance > TraceDistance bo‘lmasligi kerak; lekin qo‘shimcha “interact faqat 200 ichida” qoidasi.

1:1 Ishlagan misol — node ketma-ketligi (qisqa checklist)

Graph’da yuqoridan pastga taxminan shunday ko‘rinishi kerak (Comment ichida):

  1. Event Tick
  2. Get Camera (component) → Get World Location → promote yoki to‘g‘ridan Start
  3. Same Camera → Get Forward Vector
  4. Multiply (Forward, TraceDistance)
  5. Add (Location, Multiply result) → End
  6. Line Trace By Channel (Start, End, Visibility, Ignore Self)
  7. Branch (Return Value)
  8. True: Break Hit Result → Set CurrentFocusedActor, Set bHasFocus true
  9. False: Clear CurrentFocusedActor, Set bHasFocus false
  10. Optional: Branch bDrawInteractionDebug → Draw Debug Line

Compile → PIE → Show Collision ixtiyoriy → nishonga qarang.

? Tez-tez so‘raladigan savollar

Trace har frame — o‘yin sekinlashadimi?
Bitta qisqa Line Trace odatda sezilmaydi. Minglab mesh yoki multiplayer da 60 client har biri murakkab multi-trace qilsa — boshqa masala. Hozirgi loyiha uchun xavfsiz.
Nima uchun eshik “ko‘rinmayapti”?

1) Collision preset: No Collision yoki Visibility Ignore.

2) Faqat Query overlap, Block yo‘q.

3) Trace Complex true, lekin mesh’da complex collision yo‘q.

4) Eshik boshqa Actor ichida, hit parent’ga tushyapti — Hit Actor’ni Print qilib qarang.

Crosshair markazi bilan trace mos kelmayapti
UI crosshair ekran markazi; kamera forward ham odatda markaz. Agar FOV yoki offset bo‘lsa, Deproject Screen to World ishlatiladi (murakkabroq). Hozircha camera forward yetarli.
First person bo‘lsa nima o‘zgaradi?
Start ko‘pincha camera yoki socket “face”. Mantiq bir xil. Bu loyiha third person — SpringArm orqasidagi camera.
Kun 5 dagi Interface bilan bog‘liqligi?
Kun 5 da “qanday gaplashish” o‘rgandingiz. Bugun “kim bilan gaplashish kerakligini” topasiz. Ertaga ikkisini ulang: Focus Actor + Does Implement Interface + Message.
