Bugungi aniq maqsad

Barcha item’lar uchun asos bo‘ladigan BP_Item Actor klassini yaratish. Undan meros oluvchi BP_Item_Key va BP_Item_Battery child Blueprint’larni yasash. BPI_Interact interfeysini ulab, interaction matnini dinamik qilish.

01 Nima uchun bu kun juda muhim?

Ko‘p o‘quvchilar bu kunni “oddiy variable qo‘yish” deb o‘ylashadi. Bu xato. Bugun siz qilayotgan narsa — butun o‘yin iqtisodiyoti va progression tizimining asosi.

O‘ylab ko‘ring: o‘yinda Key, Battery, Medkit, Keycard, Fuse, Document, Weapon Part va yana 15 xil item bo‘ladi. Agar har birini alohida to‘liq Blueprint qilib yozsangiz, Pickup mantig‘ini o‘zgartirish uchun 20 ta faylni ochib chiqishingiz kerak bo‘ladi. Bu — professional dasturlashda maintainability deb ataladigan narsaning yo‘qligi.

✗

Yomon arxitektura

  • • Har item = alohida to‘liq Blueprint
  • • Pickup kodi 15 joyda takrorlanadi
  • • Yangi item qo‘shish = 30 daqiqa
  • • Bitta bug = 15 joyda tuzatish
  • • Kod bazasi tezda ifloslanadi
✓

Bizning arxitektura

  • • Bitta BP_Item parent
  • • Umumiy mantiq bir joyda
  • • Yangi item = 2 daqiqa (child + data)
  • • Bitta joyda tuzatish = hammasi tuzaladi
  • • Kelajakda Data Table’ga oson o‘tish

Professor eslatmasi

50 yillik tajribamda ko‘rgan eng katta xato — “hozircha ishlasa bo‘ldi” deb arxitekturani e’tiborsiz qoldirish. Item System — o‘yinning qon tomiri. Uni boshidan to‘g‘ri qilsangiz, keyingi 60 kun tinch o‘tadi. Noto‘g‘ri qilsangiz — Day 50 atrofida hammasi qulab tushadi va qayta yozishga majbur bo‘lasiz.

02 Nazariya — chuqur tushuntirish

BP_Item nima?

BP_Item — bu Abstract Parent Class (garchi Unreal’da rasman Abstract deb belgilamasak ham). Uning vazifasi — barcha item’larga umumiy bo‘lgan xususiyatlar va xatti-harakatlarni bir joyda saqlash.

Real hayotdan misol: “Meva” degan tushunchani oling. Olma, Banan, Apelsin — hammasi Meva. Ularda umumiy narsalar bor: rang, vazn, shirinligi, yeyish mumkinligi. Lekin har birining o‘ziga xos tomoni ham bor. BP_Item — bu “Meva”. BP_Item_Key — bu “Olma”.

Nima uchun Actor, Component emas?

Ba’zi dasturchilar Item’ni Actor Component qilib yasashni tavsiya qiladi. Bu ham ishlaydi, lekin bizning holatda Actor to‘g‘riroq tanlov, chunki:

  • Item dunyoda mustaqil mavjud bo‘lishi kerak (pickup qilinmaguncha)
  • Uning o‘z Transform’i, Collision’i, Mesh’i bor
  • Line Trace uni to‘g‘ridan-to‘g‘ri urishi kerak
  • Keyinchalik replicatsiya (multiplayer) uchun Actor qulayroq

04 Variable’lar — har birining chuqur tahlili

ItemID (Name)

Bu — item’ning tizim ichidagi pasporti. O‘yinchiga ko‘rinmaydi. Faqat kod ishlatadi: “Bu qaysi item?”, “Inventory’da bormi?”, “Eshik qaysi kalitni talab qiladi?”

Nima uchun Name, String emas?

Name tipida solishtirish tezroq (hash orqali). String’da har safar belgi-belgi solishtiriladi. 1000 marta solishtirishda farq seziladi.

Naming Convention

PascalCase yoki oddiy: Key, Battery, Medkit, Keycard_Red. Bo‘sh joy ishlatmang.

ItemName (String)

O‘yinchiga ko‘rsatiladigan nom. Interaction matnida, Inventory UI’da, log’larda chiqadi. Bu yerda o‘zbekcha yoki o‘yin tilida yozishingiz mumkin: “Eski kalit”, “Energiya batareyasi”.

Maslahat: Kelajakda lokalizatsiya (ko‘p tillilik) qilsangiz, ItemName o‘rniga String Table Key ishlatiladi. Hozircha oddiy String yetarli.

ItemIcon (Texture2D)

Inventory UI’da ko‘rsatiladigan kichik rasm. Hozircha None qoldirish mumkin — Day 66’da UI yasaganimizda to‘ldiramiz. Lekin variable’ni bugun qo‘yib qo‘yamiz, chunki keyin qo‘shish strukturani buzishi mumkin.

ItemDescription (String)

Item haqida qisqa tavsif. Tooltip’da, Computer ekranida yoki Examination UI’da ishlatilishi mumkin. Masalan: “Zanglagan, lekin hali ishlaydi. Qizil eshiklarni ochadi.”

05 Inheritance — meros olish qanday ishlaydi?

Unreal Engine’da Child Blueprint yaratganingizda, u Parent’ning barcha narsasini meros qilib oladi:

  • Barcha Variable’lar (va ularning default qiymatlari)
  • Barcha Component’lar (Static Mesh, Collision va h.k.)
  • Barcha Funksiyalar va Event’lar
  • Implement qilingan Interface’lar
  • Class Settings (Replication, Tick va h.k.)

Child’da siz faqat farq qiladigan narsalarni o‘zgartirasiz yoki qo‘shasiz. Masalan, BP_Item_Keyda faqat ItemID = Key va ItemName = "Eski kalit" deb qo‘yasiz. Qolgani hammasini parent’dan oladi.

Muhim ogohlantirish

Parent’dagi variable’ni child’da “Override Default” qilib o‘zgartirsangiz — bu faqat shu child uchun amal qiladi. Parent’ni o‘zgartirsangiz, override qilinmagan child’lar yangi qiymatni oladi, override qilinganlar esa o‘z qiymatini saqlaydi.

2

BP_Item Parent Class yaratish

Barcha item’larning ota-klassi

  1. Items papkasida o‘ng tugma → Blueprint Class
  2. Parent Class sifatida Actor ni tanlang (eng yuqoridagi)
  3. Nomini aniq BP_Item deb yozing (katta-kichik harf muhim)
  4. Enter bosing va Blueprint’ni oching

Nima uchun Actor? Actor — Level’ga joylashtirish mumkin bo‘lgan eng asosiy klass. Uning Transform’i, Component hierarchy’si va Replication qo‘llab-quvvatlashi bor. Pawn yoki Character emas, chunki Item yurmaydi va o‘yinchi boshqarmaydi.

3

Component’larni qo‘shish

Mesh + Collision — item’ning jismoniy mavjudligi

  1. Components panelida Add Component → Static Mesh ni qidiring va qo‘shing.
    Nomini ItemMesh deb o‘zgartiring (ixtiyoriy, lekin tavsiya).
  2. Yana Add Component → Box Collision qo‘shing.
    Bu Line Trace va overlap uchun kerak.
  3. Box Collision’ni tanlab, Details’da:
    • Box Extent ni Mesh’ga mos qilib kattalashtiring (masalan 30×30×30)
    • Collision Preset → OverlapAllDynamic yoki Custom qilib Query’ni yoqing
  4. Static Mesh’ga vaqtinchalik biror mesh qo‘ying (masalan Engine Content’dan Shape_Cube yoki Shape_Sphere).
Component Hierarchy
BP_Item (Actor)
├── DefaultSceneRoot  (yoki ItemMesh Root qilishingiz mumkin)
├── ItemMesh          (Static Mesh Component)
└── BoxCollision      (Box Collision Component)
4

Variable’larni yaratish

Item’ning “pasporti”

My Blueprint panelida + Variable tugmasini bosib, quyidagi 4 ta variable’ni yarating:

# Variable Name Type Instance Editable Expose on Spawn Default
1 ItemID Name ✓ Ha ✓ Ha None

Expose on Spawn — Spawn Actor node’da pin sifatida chiqadi (Pickup’dan keyin Drop qilganda foydali).

08 Keng tarqalgan xatolar va yechimlari

1. “Create Child Blueprint Class” chiqmayapti

Sabab: Parent Blueprint compile qilinmagan yoki saqlanmagan. Yechim: BP_Item’ni ochib Compile + Save qiling, keyin qayta urinib ko‘ring. Agar baribir chiqmasa — Content Browser’da BP_Item’ni tanlab, yuqoridagi “Blueprint” menyusidan “Create Child” ni qidiring.

2. Variable Details’da ko‘rinmayapti (Instance Editable yoqilmagan)

Variable’ni tanlang → Details panelida Instance Editable checkbox’ini yoqing. Eye ikonka ham ochiq bo‘lishi kerak. Compile qiling.

3. GetInteractionText’da ItemName “None” yoki bo‘sh chiqyapti

Child Blueprint’da Class Defaults ichida ItemName to‘ldirilganini tekshiring. Agar parent’da default "Item" bo‘lsa va child’da override qilinmagan bo‘lsa — "Item" chiqadi. Child’da aniq qiymat bering.

4. BPI_Interact topilmayapti

BPI_Interact Day 16’da yaratilgan bo‘lishi kerak. Agar yo‘q bo‘lsa — avval uni yarating (Blueprint Interface, ichida GetInteractionText, CanInteract, Interact funksiyalari bilan). Keyin qaytib kelib implement qiling.

5. Box Collision Line Trace’ni ushlamayapti

Collision Preset’ni tekshiring. “NoCollision” bo‘lmasligi kerak. Eng xavfsiz: Custom → Collision Enabled = Query Only → Object Type = WorldDynamic → Visibility yoki Camera Trace channel’ini Block qiling.

★ Professor izohi — nima uchun bu kun shunday qurilgan?

Men 50 yil davomida yuzlab o‘quvchilarga o‘yin dasturlashni o‘rgatdim. Eng katta farq “ishlaydigan kod yozadigan” va “professional kod yozadigan” odam o‘rtasida — abstraksiya darajasida.

Bugun siz abstraksiya yaratyapsiz. BP_Item — bu abstraksiya. U aytadi: “Men bilaman, barcha item’larning nomi, ID’si, ikonkasi bor. Ularning qanday ko‘rinishi va nima qilishi keyinroq aniqlanadi.”

Bu yondashuvni o‘zlashtirsangiz — keyingi loyihalaringizda ham (hatto Unreal bo‘lmaganida ham) shu prinsiplardan foydalanasiz. Inheritance, Interface, Data-driven design — bular dasturlashning abadiy qonunlari. Bugun ularni amalda qo‘llayapsiz.

→ Keyingi kun — Day 30: Pickup

Ertaga biz bugun yaratgan strukturaga hayot bag‘ishlaymiz. Item’ni o‘yinchi qarab E bosganda:

  • Item ma’lumoti Player’ning Inventory Array’iga yoziladi
  • Item dunyodan yo‘qoladi (Destroy Actor)
  • Print String orqali “Key olindi!” kabi xabar chiqadi

Bugun yasagan BP_Item va BPI_Interact shu mantig‘ning asosi bo‘ladi. Shuning uchun bugun hammasini to‘g‘ri va toza qilib qo‘ying.
