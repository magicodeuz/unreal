Bugungi aniq maqsad

Item ma’lumotlarini Actor ichidan Data Table’ga ko‘chirib, professional darajadagi ma’lumot boshqaruviga o‘tish. DT_Items yaratish, qatorlarni to‘ldirish, BP_Item BeginPlay’da o‘qib olish.

01 Nima uchun Data Table kerak?

Hozirgacha har bir child Blueprint’da (BP_Item_Key, BP_Item_Battery…) ItemName, ItemDescription ni qo‘lda yozganmiz. 5 ta item bo‘lsa — chidasa bo‘ladi. 50 ta bo‘lsa — do‘zax.

Data Table — bu Excelga o‘xshash jadval. Bitta joyda barcha item’larning nomi, tavsifi, ikonkasi turadi. Dizayner balansni o‘zgartirmoqchi bo‘lsa — Blueprint ochmasdan, faqat jadvalni tahrirlaydi.

Professor eslatmasi

AAA o‘yinlarda item, qurol, dushman, quest — hammasi Data Table yoki Data Asset orqali boshqariladi. Kod (Blueprint/C++) faqat “qanday ishlashni” biladi, “nima ekanligini” esa ma’lumot belgilaydi. Bu ajratish data-driven design deb ataladi. Bugun shu falsafaga o‘tasiz.

02 Nazariya — Data-driven design

Data Table nima?

Data Table — Unreal’dagi maxsus asset. U Struct asosida quriladi (bizda S_ItemData). Har bir qator (Row) — bitta item. Har bir ustun — Struct maydoni (ItemID, ItemName, Icon…).

Muhim: Row’ning o‘zi ham nomga ega. Odatda bu nomni ItemID bilan bir xil qilamiz: Key, Battery, Medkit. Shunda Get Data Table Row da Row Name sifatida ItemID ni berib, to‘g‘ri qatorni topamiz.

Ishlash tartibi

BeginPlay (BP_Item)
↓
Get Data Table Row
DT_Items + Row Name = ItemID
↓
Break S_ItemData
ItemName, Icon, Description ajratiladi
↓
Set local variables
ItemName, ItemIcon, ItemDescription

03 Eski vs Yangi yondashuv

Eski (Day 29–31)
  • • Har child’da ItemName qo‘lda yoziladi
  • • Yangi item = yangi child Blueprint
  • • Nom o‘zgartirish = Blueprint ochish
  • • 20 item = 20 joyda tahrirlash
  • • Dizayner kodga tegishi kerak
Yangi (bugundan)
  • • Barcha ma’lumot DT_Items da
  • • Yangi item = yangi qator (+ ixtiyoriy child)
  • • Nom o‘zgartirish = jadvalni tahrirlash
  • • 20 item = bitta jadval
  • • Dizayner faqat Data Table bilan ishlaydi

04 DT_Items yaratish

  1. Content Browser’da Content/BetrayBuilder/Data/ papkasini yarating (yo‘q bo‘lsa)
  2. O‘ng tugma → Miscellaneous → Data Table
  3. Row Structure sifatida S_ItemData ni tanlang
  4. Nomini DT_Items deb qo‘ying
  5. Save

Agar S_ItemData ro‘yxatda chiqmasa — avval uni Compile/Save qiling (Day 31’da yaratilgan). Data Table faqat saqlangan Struct’lardan foydalanadi.

05 Qatorlarni to‘ldirish

DT_Items ni oching. Yuqoridagi Add tugmasi bilan yangi qator qo‘shing. Har bir qator uchun:

Row Name ItemID ItemName Icon
Key Key Eski kalit None (hozircha)
Battery Battery Energiya batareyasi None
Medkit Medkit Tibbiy to‘plam None

Row Name = ItemID bo‘lishi juda muhim. Get Data Table Row da biz Row Name sifatida ItemID ni beramiz. Ular mos kelmasa — qator topilmaydi.

06 BP_Item BeginPlay — ma’lumotni o‘qish

Endi BP_Item o‘zining ItemName, ItemIcon, ItemDescription ni qo‘lda saqlamaydi. BeginPlay’da Data Table’dan o‘qiydi. 

// BP_Item → Event BeginPlay

1. Get Data Table Row
   - Data Table: DT_Items
   - Row Name:   ItemID   (variable, Name tipida)
   
2. Row Found pinidan:
   - Break S_ItemData (Out Row pinidan)
   - Set ItemName      ← Break.ItemName
   - Set ItemIcon      ← Break.Icon
   - Set ItemDescription ← (agar Struct'da bo'lsa)

3. Row Not Found:
   - Print String: "ItemID topilmadi: " + ItemID
   - (ixtiyoriy) Destroy Actor yoki default qiymat

ItemID qayerda qoladi? ItemID hali ham BP_Item (yoki child) da Instance Editable variable bo‘lib qoladi. Level’ga joylashtirganda yoki child’da default qilib berasiz. Qolgan ma’lumotlar jadvaldan keladi.

09 Keng tarqalgan xatolar

1. “Row Not Found” doim ishlayapti

Row Name (Data Table’dagi) va ItemID (Blueprint’dagi) bir xil ekaniga ishonch hosil qiling. Katta-kichik harf ham muhim: Key ≠ key.

2. S_ItemData Data Table yaratishda chiqmayapti

Struct’ni ochib Save/Compile qiling. Editor’ni qayta ishga tushirish ham yordam berishi mumkin.

3. Interaction matni hali eski nomni ko‘rsatadi

GetInteractionText ItemName variable’idan o‘qiydi. BeginPlay da Set qilinganini tekshiring. Play dan oldin PIЕ ni to‘xtatib qayta ishga tushiring.

4. Child’dagi eski ItemName hali ishlatilayapti

Child Class Defaults’da ItemName ni tozalang yoki BeginPlay dagi Set uni ustiga yozadi. Tartib: BeginPlay ishlagach, jadvaldagi qiymat ustunlik qilishi kerak.

★ Qo‘shimcha Challenge

Challenge: Yangi item — faqat qator bilan

DT_Items ga to‘rtinchi qator qo‘shing: Row Name = Keycard, ItemName = "Qizil kalit-karta".

Yangi child Blueprint yaratmang. Levelga oddiy BP_Item (yoki mavjud child) qo‘ying, Details’dan ItemID ni Keycard qilib qo‘ying. Play qiling — interaction matni “Olish: Qizil kalit-karta” chiqishi kerak. Bu data-driven yondashuvning kuchi.

★ Professor izohi

Bugun siz kod va ma’lumotni ajratdingiz. Bu — professional dasturlashning eng muhim qadamidan biri. Kod “qanday” ni biladi, ma’lumot “nima” ni belgilaydi.

Kelajakda qurol statistikasi, dushman turlari, quest ma’lumotlari — hammasi shu usulda bo‘ladi. Bugun o‘rgangan narsa sizni butun karyerangiz davomida kuzatib boradi.

→ Keyingi kun — Day 33: Use Item

Ertaga Inventory’dagi item’larni haqiqiy ishlatamiz: Key → eshik ochadi, Battery → generator, Medkit → Health. Data Table va Inventory Array shu mantig‘ning asosi bo‘ladi.
