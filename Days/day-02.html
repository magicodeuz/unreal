Stage 1 · Kun 2 / 7

Actor va Component

O‘zingizning birinchi Actor Blueprint’ingizni yaratasiz, unga Static Mesh va Box Collision qo‘shasiz, hierarchy tushunchasini amalda ko‘rasiz.

🎯 Kun maqsadi

Bugun siz:

  • → Yangi Actor Blueprint yaratasiz (BP_TestObject)
  • → Unga Static Mesh Component qo‘shib, Cube modelini biriktirasiz
  • → Box Collision qo‘shib, fizik chegarani sozlaysiz
  • → Component’lar orasidagi Parent / Child bog‘lanishni tushunasiz
  • → Levelga 2–3 nusxa joylashtirib, Transform bilan sinab ko‘rasiz

Bugun qilmang: Widget Component qo‘shmang, Event Graph’da script yozmang. Faqat Component hierarchy bilan ishlang.

📖 Asosiy tushunchalar

Kecha o‘rgangan Actor tushunchasini chuqurlashtiramiz.

Actor Blueprint

Oddiy Actor’ning “shablon”i. Bir marta yaratib, Levelga istalgancha nusxa (instance) qo‘yishingiz mumkin. Har bir nusxa bir xil Component’larga ega, lekin Transform’i (joylashuvi) alohida.

Component

Actor ichidagi qism. Actor o‘zi “bo‘sh quti” — uni to‘ldiradigan narsalar Component’lar. Mesh (ko‘rinish), Collision (chegar), Light (yorug‘lik), Audio va h.k.

Static Mesh Component

3D modelni ko‘rsatadi. “Static” — animatsiyalanmaydi (skeletal emas). Cube, eshik, stol, devor — ko‘pincha Static Mesh.

Box Collision

Actor atrofida ko‘rinmas to‘rtburchak (yoki boshqa shakl) fizik chegara. Keyinchalik Overlap (kimdir ichiga kirdi) va Hit (urildi) eventlari shu orqali ishlaydi. Interaction System (Stage 3) asosan Collision’ga tayanadi.

Parent / Child Component

Component’lar daraxt (hierarchy) shaklida bog‘lanadi. Parent harakatlansa yoki aylansa — Child ham u bilan birga harakatlanadi. Masalan: Mesh Parent, Collision uning Child’i bo‘lsa — Mesh’ni ko‘chirsangiz, Collision ham ergashadi.

DefaultSceneRoot

Har bir Actor Blueprint’da avtomatik yaratiladigan ildiz (root) Component. Boshqa barcha Component’lar odatda uning ostida turadi. Uni o‘chirish mumkin emas (yoki o‘rniga boshqa root qo‘yiladi).

🌳 Bugungi maqsad hierarchy

Yakuniy Component daraxti shunday bo‘lishi kerak:

BP_TestObject
└── DefaultSceneRoot          ← ildiz (avtomatik)
      ├── StaticMeshComponent   ← vizual ko‘rinish (Cube)
      └── BoxCollision          ← fizik chegara (Parent: StaticMesh yoki Root)

Ba’zi holatlarda BoxCollision’ni to‘g‘ridan-to‘g‘ri StaticMesh ostiga (Child qilib) qo‘yish qulay — Mesh ko‘chsa, Collision ham ergashadi.

1

Actor Blueprint yaratish

Taxminiy vaqt: 5–10 daqiqa

1.1 Blueprints papkasiga o‘ting

Content Browser’da chapdagi papka daraxtidan:

Content → BetrayBuilder → Blueprints

Agar Blueprints papkasi yo‘q bo‘lsa — Kun 1 dagi strukturani qayta yarating.

1.2 Yangi Blueprint Class yaratish

Content Browser’da bo‘sh joyda o‘ng sichqoncha bosing.

Menyudan: Blueprint Class

Yoki yuqoridagi yashil + Add → Blueprint Class.

Nima ochiladi: “Pick Parent Class” oynasi. Bu yerda Blueprint qaysi turdan meros olishini tanlaysiz.

1.3 Parent Class: Actor

Ochilgan oynada yuqorida bir nechta umumiy class’lar ko‘rinadi:

  • Actor ← mana shuni tanlang
  • Pawn
  • Character
  • Player Controller
  • ...

Actor ga bir marta bosing (yoki ikki marta).

Nima uchun Actor? Chunki bizga oddiy joylashtiriladigan obyekt kerak — yurmaydi, boshqarilmaydi, faqat sahnada turadi. Character/Pawn keyinroq (Stage 2).

1.4 Nom berish

Content Browser’da yangi asset paydo bo‘ladi va nomini so‘raydi.

Nom: BP_TestObject

Enter bosing.

Nomlash: BP_ = Blueprint. Butun kursda Blueprint’lar shu prefiks bilan yuritiladi (BP_Player, BP_Door, BP_GameMode...).

Tekshirish: Content/BetrayBuilder/Blueprints/BP_TestObject ko‘rinishi kerak. Ikonka odatda ko‘k/binafsha rangdagi Blueprint belgisi.

1.5 Blueprint Editor’ni ochish

BP_TestObject ga ikki marta bosing (yoki o‘ng sichqoncha → Edit).

Yangi oyna / tab ochiladi — Blueprint Editor.

Asosiy qismlar:

  • Components (chap yuqori) — Component daraxti
  • Viewport (markaz) — shu Actor’ning 3D ko‘rinishi
  • Details (o‘ng) — tanlangan Component sozlamalari
  • My Blueprint (chap past) — Variables, Functions, Event Graph (bugun tegmaymiz)

Hozir Components panelida faqat DefaultSceneRoot turadi. Keyingi qadamda Mesh qo‘shamiz.

2

Static Mesh Component qo‘shish

Taxminiy vaqt: 10 daqiqa

2.1 Add Component

Blueprint Editor’da chapdagi Components panelini toping.

Yuqorisida + Add (yoki “Add Component”) tugmasi bor — uni bosing.

Ochilgan ro‘yxatda qidiring yoki yozing: Static Mesh

Static Mesh ni tanlang.

Natija: Components daraxtida StaticMesh (yoki StaticMeshComponent) paydo bo‘ladi. Odatda DefaultSceneRoot ostida Child sifatida qo‘shiladi.

2.2 Cube mesh’ni biriktirish

Components’da StaticMesh ni tanlang (bir marta bosing).

O‘ngdagi Details panelida Static Mesh maydonini toping (bo‘sh yoki “None”).

O‘ngdagi pastga ochiladigan ro‘yxatni bosing (yoki maydon ichiga bosing).

Qidiruvga yozing: Cube

Engine Content’dan keladigan Cube (yoki Shape_Cube) ni tanlang.

Agar Cube topilmasa: Details’dagi Static Mesh maydonida o‘ngdagi papka ikonkasini bosing → Content Browser ochiladi. Qidiruvga “Cube” yozing. Agar baribir yo‘q bo‘lsa — View Options (Content Browser pastki o‘ng) da “Show Engine Content” ni yoqing.

Tekshirish: Blueprint Viewport (markaziy 3D oyna) da endi kulrang Cube ko‘rinishi kerak. Agar ko‘rinsa — muvaffaqiyat.

2.3 Saqlash

Toolbar’dan Compile (yoki Ctrl+Alt+F7) bosing — xato yo‘qligini tekshiradi.

Keyin Save (Ctrl+S).

Compile muvaffaqiyatli bo‘lsa, yashil belgi chiqadi. Qizil xato bo‘lsa — pastdagi Compiler Results panelida sababini o‘qing (bugun odatda xato bo‘lmasligi kerak).

3

Box Collision qo‘shish

Taxminiy vaqt: 10–15 daqiqa

3.1 Box Collision Component qo‘shish

Yana Components panelida + Add bosing.

Qidiring: Box Collision

Tanlang. Daraxtga Box (yoki BoxCollision) qo‘shiladi.

Eslatma: Collision Component odatda Viewport’da ko‘rinmas (yashirin). Uni ko‘rish uchun keyinroq “Show Collision” yoqamiz. Hozircha Details orqali sozlaymiz.

3.2 Collision o‘lchamini sozlash

Components’da Box ni tanlang.

Details panelida Shape yoki Box Extent bo‘limini toping.

Box Extent — yarim o‘lcham (markazdan chetga). Cube taxminan 50×50×50 unit atrofida bo‘ladi (engine Cube o‘lchamiga qarab).

Collision Mesh’dan biroz kattaroq bo‘lishi kerak — o‘yinchi yaqinlashganda “ushlab” olish uchun.

Misol qiymatlar (sinab ko‘ring):

  • Box Extent X: 55
  • Box Extent Y: 55
  • Box Extent Z: 55

Yoki Viewport’da Box tanlang → R (Scale mode) → gizmo bilan biroz kattalashtiring. Lekin Extent orqali aniqroq.

3.3 Collision joylashuvini tekshirish

Box Collision markazi Mesh markazi bilan ustma-ust tushishi kerak.

Agar Box uzoqda turgan bo‘lsa — Details → Transform → Location ni 0, 0, 0 qiling (relative to parent).

Compile + Save qiling.

4

Parent / Child bog‘lanish

Taxminiy vaqt: 5–10 daqiqa

4.1 Hierarchy’ni ko‘rish

Components panelida daraxt taxminan shunday:

DefaultSceneRoot
  ├── StaticMesh
  └── Box

Ikkalasi ham Root’ning Child’i. Bu yaxshi ishlaydi.

Ixtiyoriy yaxshilash: Box’ni StaticMesh’ning Child’i qilish — Mesh’ni local space’da siljitsangiz, Collision ham ergashadi.

4.2 Parent’ni o‘zgartirish (ixtiyoriy)

Components’da Box ni sichqoncha bilan ushlab, StaticMesh ustiga tashlang (drag & drop).

Daraxt endi shunday bo‘ladi:

DefaultSceneRoot
  └── StaticMesh
        └── Box

Bu — Parent/Child bog‘lanish. StaticMesh Parent, Box uning Child’i.

Nima o‘zgaradi? StaticMesh’ning relative Location/Rotation/Scale’ini o‘zgartirsangiz, Box ham u bilan birga siljiydi. Root’ni (butun Actor’ni) ko‘chirsangiz — hammasi birga ko‘chadi (bu har doim shunday).

4.3 Compile va Save

Compile → Save. Blueprint Editor’ni yopishingiz mumkin (yoki ochiq qoldiring).

5

Levelga joylashtirish

Taxminiy vaqt: 10 daqiqa

5.1 Level’ni ochish

Asosiy Editor oynasiga qayting (Level Viewport).

Kun 1 dagi MAP_Day01 ni oching yoki yangi bo‘sh Level yarating va saqlang.

Content Browser’da BP_TestObject ni toping.

5.2 Nusxalarni joylashtirish

BP_TestObject ni Content Browser’dan Viewport’ga sudrab tashlang.

Yana 1–2 marta tashlang — jami 2 yoki 3 ta instance bo‘lsin.

Har birini tanlab, turli joyga ko‘chiring (W + gizmo yoki Details → Location).

Masalan:

  • Birinchisi: Location 0, 0, 50
  • Ikkinchisi: Location 300, 0, 50 · Scale 2, 2, 2
  • Uchinchi: Location -300, 100, 50 · Rotation 0, 45, 0

Muhim: Bu yerda o‘zgartirayotganingiz — instance’ning Transform’i. Blueprint ichidagi Component hierarchy o‘zgarmaydi. Bitta BP_TestObject’da Mesh o‘zgartirsangiz — barcha instance’lar yangilanadi.

5.3 Level’ni saqlash

Ctrl + S — Level saqlansin.

6

Test qilish — Collision ko‘rinishi

Taxminiy vaqt: 5–10 daqiqa

Show Collision

Viewport’da biror BP_TestObject instance’ini tanlang.

Viewport yuqorisidagi menyudan (yoki Viewport ichida o‘ng burchakdagi “Show” / “View Mode”:

Show → Collision (yoki View → Show → Collision — versiyaga qarab).

Ba’zi versiyalarda: Viewport chap yuqorisidagi Lit yoki ko‘z ikonkasi → Player Collision / Collision.

Yoqilganda Cube atrofida yashil (yoki binafsha) simli to‘rtburchak — Box Collision — ko‘rinishi kerak.

Muvaffaqiyat: Collision Mesh atrofida, biroz kattaroq, markazlashtirilgan bo‘lsa — to‘g‘ri sozlangan.

Agar Collision ko‘rinmasa yoki noto‘g‘ri joyda bo‘lsa:

  • BP_TestObject’ni qayta oching → Box tanlang → Location 0,0,0 va Extent’ni tekshiring
  • Compile + Save qiling, keyin Level’dagi instance’lar avtomatik yangilanadi
  • Show Collision haqiqatan yoqilganiga ishonch hosil qiling
Play bilan qisqa tekshiruv

Play bosing. Uchala (yoki ikkala) BP_TestObject ko‘rinishi kerak. Hozircha ular bilan interact qilishning iloji yo‘q — bu keyingi kunlar. Faqat vizual va joylashuvni tekshiring.

Esc bilan chiqing.

★

Challenge (ixtiyoriy)

Uchinchi Component — Point Light

BP_TestObject’ga yorug‘lik qo‘shing:

  1. BP_TestObject’ni oching (ikki marta bosing).
  2. Components → + Add → Point Light.
  3. Point Light’ni tanlang → Details:
    • Intensity — masalan 2000–5000
    • Light Color — istalgan rang (masalan och ko‘k yoki sariq)
    • Attenuation Radius — masalan 500
  4. Location’ni biroz yuqoriga ko‘taring (masalan Z = 80), shunda yorug‘lik Cube tepasidan tushsin.
  5. Compile + Save.
  6. Level’da instance’larga qarang — endi ular atrofida yorug‘lik bo‘lishi kerak (Lumen/dynamic lighting yoqilgan bo‘lsa).

Bu challenge hierarchy’ga yana bitta Component qo‘shishni mustahkamlaydi va keyinroq Light Switch / Sabotage uchun foydali bo‘ladi.
