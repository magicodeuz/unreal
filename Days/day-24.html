Doors & Windows

Proyomlar → BP_Door instansiyalari. Oyna — vizual “ko‘rinish”; qulf yo‘q (Day 33).

🎯 Kun maqsadi

  • → Har proyomga BP_Door (Day 17)
  • → Nom: BP_Door_Office, BP_Door_Utility…
  • → Ochilish yo‘nalishi xonani to‘smasin
  • → 2–3 Window (shaffof mesh, asosan vizual)

Bugun qilmang: Qulflash, kalit, auto-close murakkabligi. Faqat joylash + swing + interact.

? Nima uchun endi eshik?

Kun 22–23: bo‘shliq va nom. Endi Stage 3 Interaction xaritaga kiradi — xonalar “o‘ynaladigan” bo‘ladi.

Eshik = tempo (ochish vaqti), ovoz (keyin), kim qayerda ekanligi. Window = “ko‘rinamanmi?” — betrayal uchun psixologiya.

17 BP_Door (Day 17) eslatma

Timeline + Lerp Rotator + BPI_Interact. Instance Editable OpenAngle (±90).

Agar BP_Door yo‘q / buzilgan — avval MAP_InteractionTest da tuzating, keyin nusxa ko‘chiring.

Levelga instance joylashtirasiz — class asset emas, har eshik alohida Actor.

↗ Ochilish yo‘nalishi (swing)

Eshik ochilganda panel koridor yoki xona ichidagi meshga urilmasligi kerak.

  • Pivot menteşe — to‘g‘ri tomonda
  • OpenAngle +90 yoki −90 — Details / variable
  • Tor koridorda: eshik xona ichiga ochilsin (yoki sliding keyin)

Play da ochib ko‘ring; tiqilsa burchakni aylantiring.

🪟 Windows — vizual, deyarli gameplay yo‘q

Oddiy plane/cube + shaffof material (yoki Translucent default). Collision: Query only yoki NoCollision — o‘tish shart emas; ba’zan Block (oyna sindirish keyin).

Ideal joy: Security ↔ Office / Hallway — “kimdir monitor oldida”. Betrayal mechanic keyin shu hissiyotdan foydalanadi.

2–3 ta yetarli. Har devorga oyna shart emas.
